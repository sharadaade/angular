Start Here: Angular Learning Roadmap

Build understanding before memorizing interview answers. The running domain is a hospitality booking application with an Angular frontend and an ASP.NET Core API.

What this course covers

Definition: A learning roadmap orders concepts so later lessons use skills you already understand.

Study web and TypeScript prerequisites, components/templates, dependency injection, signals, RxJS, routing, forms, HTTP, testing, security, performance, architecture, and projects. Read the definition, predict the code, follow the walkthrough, then solve the exercise. Interview answers should connect an implementation choice to an observable result and its tradeoffs. This is a broad language-and-platform curriculum, not a claim to list every third-party library or every employer’s questions.

Real project use: Use the course to build a room catalog, booking form, guarded dashboard, and API integration rather than isolated snippets.

Typescript · learning example
// Running domain used by later snippets
export interface Room {
  id: number;
  name: string;
  price: number;
  available: boolean;
}

Code explained:

  1. Room models a record returned by the application API.
  2. Numeric IDs and prices, text names, and boolean availability are checked at development time.
  3. External JSON must still be validated at runtime before it is trusted.
Mistake to avoid
Finishing a chapter by copying code without explaining or changing it does not demonstrate mastery.

Version baseline and legacy coverage

Definition: A framework version determines available APIs, defaults, and migration requirements.

The course follows Angular 22-era official documentation checked on 9 October 2026. Examples explicitly use standalone components and OnPush where useful. Zoneless is the default in Angular 21+ and OnPush is the default from Angular 22; older projects can behave differently. Current CLI test defaults use Vitest, while many existing projects use Jasmine/Karma. New and evolving APIs are identified separately. Use the installed project version and its documentation when applying a snippet.

Real project use: Read ng version and package.json before modifying a company repository.

Bash · learning example
ng version
# In an existing repository, use its locked dependencies.
npm ci
# Run the project
npm start

Code explained:

  1. ng version reports the Angular/CLI versions and environment information.
  2. npm ci installs according to the lockfile instead of silently choosing arbitrary dependency versions.
  3. npm start uses the repository’s own script, which may differ between projects.
Mistake to avoid
Do not migrate a production project merely because a tutorial uses a newer API.

Lesson 2 · Foundations · Beginner

HTML, CSS, JavaScript & TypeScript Prerequisites

Angular does not replace the browser platform. Its templates and classes run on top of familiar web behavior.

HTML and semantic controls

Definition: HTML describes document structure and the meaning of elements.

A button supports activation and keyboard interaction; a form supports submission; a label connects text to an input. Use these native capabilities before inventing interaction with clickable divs. CSS controls presentation, and JavaScript handles runtime behavior. An Angular template adds bindings and control flow to HTML; it still needs valid, accessible structure.

Real project use: Build an accessible booking form that works with keyboard input and browser validation.

Markup · learning example
<form>
  <label for="guest">Guest name</label>
  <input id="guest" name="guest" required>
  <button type="submit">Book</button>
</form>

Code explained:

  1. The label names the input through the matching for/id values.
  2. The input’s name lets form serialization identify the field.
  3. The button submits the form because its type is submit.
Mistake to avoid
A button inside a form defaults to submitting unless you explicitly use type="button" for a non-submit action.

TypeScript contracts and JavaScript behavior

Definition: TypeScript checks types while JavaScript defines what happens when the code executes.

Know arrays, object references, functions, closures, this, promises, optional chaining, modules, and equality. Interfaces and generic arguments are mostly erased. An HTTP generic cannot validate JSON. A shallow object copy does not clone nested objects. These details are often the underlying cause of Angular bugs rather than a framework-specific issue.

Real project use: Keep an edited room separate from its original record and validate API data at boundaries.

Typescript · learning example
const room = { id: 201, details: { name: "Single" } };
const copy = { ...room };
copy.details.name = "Double";
console.log(room.details.name);

Code explained:

  1. Spread creates a new outer object.
  2. Both objects still point to the same details object.
  3. The log prints Double because the nested object was mutated.
Mistake to avoid
Do not describe object spread as a deep clone.

Interview practice

Why learn JavaScript if Angular uses TypeScript?

TypeScript preserves JavaScript runtime behavior. Closures, identity, promises, event timing, and array operations still determine whether the application behaves correctly.

Try it yourself

Create a copy that changes details.name without changing the original.

Show a possible solution

const copy = { ...room, details: { ...room.details, name: "Double" } };

Lesson 3 · Foundations · Beginner

JavaScript Bridge: Functions, Arrays & Objects

Before Angular, learn how the data in a component is changed. These examples run as plain JavaScript; interfaces are introduced afterward.

Functions, parameters, return values and arrow functions

Definition: A function is reusable work with named inputs and an optional returned result.

Why and when to use it: Use functions to calculate totals or transform data. A parameter receives a value from the caller. return sends a result back; console.log only displays a message. Arrow functions are common in callbacks and capture this from their surrounding scope.

Real project scenario: Calculate the room cost before rendering an estimate.

Independent learning snippet · javascript
function calculateTotal(price, nights) {
  return price * nights;
}
const total = calculateTotal(120, 3);
const addTax = amount => amount * 1.1;
console.log(total, addTax(total));

Code explained step by step:

  1. 120 and 3 are arguments assigned to price and nights.
  2. The function returns 360, so total stores a number.
  3. addTax receives 360 and returns about 396; decimal money rules belong in an explicit business policy.

Expected behavior: The console shows 360 and approximately 396. Angular templates can display the result, but the server must confirm the booking total.

Mistake to avoid
A function that only logs a value returns undefined unless it explicitly returns a result.

map, filter and find are different operations

Definition: map transforms each item, filter keeps matching items, and find returns the first matching item or undefined.

Why and when to use it: A catalog often needs a transformed display list, a filtered available list, and one selected room. Choosing the right operation expresses the intended result and avoids accidental nested loops or wrong return types.

Real project scenario: Show available rooms and locate the room selected by a route.

Independent learning snippet · javascript
const rooms = [
  { id: 1, name: "Garden", available: true },
  { id: 2, name: "City", available: false }
];
const names = rooms.map(room => room.name);
const available = rooms.filter(room => room.available);
const selected = rooms.find(room => room.id === 2);
console.log(names, available.length, selected?.name);

Code explained step by step:

  1. map returns two strings without modifying rooms.
  2. filter returns a new array containing only Garden.
  3. find returns the City object; optional chaining safely handles a missing match.

Expected behavior: names is ["Garden", "City"], available.length is 1, selected?.name is "City".

Mistake to avoid
map is not a filter: returning undefined still leaves an element in the mapped array. find does not return an array.

for...in, for...of and forEach

Definition: for...in enumerates enumerable string keys; for...of iterates iterable values; forEach calls a callback for each present array item.

Why and when to use it: Use Object.keys/Object.entries or deliberate own-property checks for objects. Use for...of for arrays when you need break/continue or sequential await. Use forEach for straightforward synchronous side effects; it neither returns a transformed array nor waits for asynchronous callbacks.

Real project scenario: Inspect a booking object and process selected room IDs.

Independent learning snippet · javascript
const booking = { roomId: 2, nights: 3 };
for (const [key, value] of Object.entries(booking)) {
  console.log(key, value);
}
const ids = [1, 2, 3];
for (const id of ids) {
  if (id === 2) break;
  console.log(id);
}
ids.forEach((id, index) => console.log(index, id));

Code explained step by step:

  1. Object.entries returns own enumerable string key/value pairs.
  2. for...of sees values and can stop at 2.
  3. forEach visits the present entries and gives both value and index.

Expected behavior: The first loop prints booking fields, the second prints only 1, and forEach logs all three ID/index pairs.

Mistake to avoid
for...in on an array may include other enumerable properties and keys are strings. await inside forEach does not make the outer function wait.

Immutability, references and private ownership

Definition: Objects are references; an immutable update creates a replacement instead of changing shared data in place.

Why and when to use it: A component and a service may hold references to the same record. Use new arrays/objects for intended reactive updates, and do not expose internal writable state unnecessarily. Spread is shallow, so nested objects still require deliberate copies.

Real project scenario: Update a selected booking without modifying the original record.

Independent learning snippet · javascript
const original = { id: 1, guest: { name: "Sharad" } };
const edited = {
  ...original,
  guest: { ...original.guest, name: "Asha" }
};
console.log(original.guest.name, edited.guest.name);

Code explained step by step:

  1. The outer spread copies top-level properties.
  2. The nested spread gives edited its own guest object.
  3. Changing edited.guest later does not change original.guest.

Expected behavior: The output is Sharad Asha.

Mistake to avoid
const prevents reassignment of the variable; it does not freeze the referenced object.

Interview practice

When should you use map instead of forEach?

Use map when you need a new transformed array. forEach is for synchronous side effects and returns undefined.

Why is find potentially undefined?

The array may contain no matching element. A type assertion does not create a missing item.

Try it yourself

Produce the names of available rooms without changing the original array.

Show a possible solution

Use rooms.filter(room => room.available).map(room => room.name). Explain that both operations return new arrays.

Lesson 4 · Foundations · Beginner

JavaScript Bridge: Async Work, Modules & Events

Requests and user actions happen over time. Understand these rules before debugging an Angular subscription.

Promise, async and await

Definition: A Promise eventually settles to one fulfillment or rejection; an async function always returns a Promise.

Why and when to use it: await pauses that async function until settlement; it does not block the entire browser. try/catch catches awaited rejection. Independent tasks may run concurrently; sequential await is useful when the next step depends on the previous result.

Real project scenario: Explain why a confirmation appears only after an operation succeeds.

Independent learning snippet · javascript
async function demonstrate() {
  try {
    const status = await Promise.resolve("confirmed");
    console.log(status);
  } catch (error) {
    console.error("Operation failed", error);
  }
}
console.log("start");
void demonstrate();
console.log("end");

Code explained step by step:

  1. The first synchronous log prints start.
  2. await yields even for an already-fulfilled Promise.
  3. The surrounding code logs end before the continuation logs confirmed.

Expected behavior: The output order is start, end, confirmed.

Mistake to avoid
A try/catch surrounding an unawaited asynchronous call will not reliably catch its later rejection. Handle the returned Promise.

Browser event versus framework output

Definition: A browser event represents an interaction on a DOM target; a component output represents an application-defined event contract.

Why and when to use it: Use native input/change/submit/focus/blur/keydown events for controls and Angular outputs for child-to-parent intent. input fires as values change; change usually represents a committed change. blur indicates leaving a control. submit belongs on the form so keyboard submission is covered.

Real project scenario: Handle a room-search input without an unsafe global cast.

Independent learning snippet · typescript
// Method inside a component:
onSearch(event: Event): void {
  const target = event.target;
  if (target instanceof HTMLInputElement) {
    this.query.set(target.value);
  }
}
// Template: <input (input)="onSearch($event)">

Code explained step by step:

  1. EventTarget is broad, so target.value is not valid without narrowing.
  2. instanceof proves this target is an input in the browser event handler.
  3. The signal update supplies the value used by the view.

Expected behavior: Typing updates the search state when this handler is bound to an input.

Mistake to avoid
Do not put window/HTMLInputElement work into unconditional server-rendered initialization. This check belongs to a browser user-event path.

Modules, imports and exports

Definition: A module exposes selected names through export and consumes them through import.

Why and when to use it: Separate files prevent an all-in-one application class. A TypeScript import makes a symbol available to code; Angular component imports metadata separately exposes directives/components/pipes to the template. These two import systems solve different problems.

Real project scenario: Put a Room interface in a model file and import it into a data service.

Independent learning snippet · typescript
// room.model.ts
export interface Room { id: number; name: string; price: number; }

// A separate consumer file:
import type { Room } from "./room.model";
const room: Room = { id: 1, name: "Garden", price: 120 };

Code explained step by step:

  1. The model file exports its named type.
  2. import type makes the type available without implying a runtime value.
  3. The object assignment is checked while external JSON still needs runtime validation.

Expected behavior: A missing required property or wrong property type produces a TypeScript diagnostic.

Mistake to avoid
An interface cannot be an Angular injection token by itself because it is erased at runtime.

Interview practice

Can await freeze the browser?

Await yields the async function. CPU-heavy synchronous work before or after it can still block the main thread.

What is the difference between input and submit?

input reports a field value change; submit represents form submission, including supported keyboard submission.

Try it yourself

Explain how loading/error/success fit into an asynchronous request.

Show a possible solution

Set loading when starting; consume the result as success; map rejection/error to a useful failure; clear loading for every terminal outcome.

Lesson 5 · Foundations · Beginner

What Angular Is & How an App Runs

Angular is a component-based web framework with integrated template compilation, dependency injection, forms, routing, and HTTP support.

Components, services, and framework libraries

Definition: A component connects a template to behavior; a service provides reusable behavior; framework libraries solve cross-cutting UI needs.

A component tree describes the screen. Services handle work such as API access or shared state without requiring a template. The router selects views by URL. Forms libraries manage input and validation. HttpClient handles network streams. The separation is architectural rather than a requirement that every function must have its own service.

Real project use: A RoomList component displays rooms supplied by a RoomApi service; a BookingForm component collects input.

None · learning example
// Suggested feature layout
rooms/
  room-list.ts
  room-card.ts
  room-api.ts
  room.model.ts
bookings/
  booking-form.ts
  booking-api.ts

Code explained:

  1. Files are organized by feature so related behavior stays close together.
  2. UI files own presentation; API files own transport and boundary concerns.
  3. Shared code moves out only when there is a real second consumer.
Mistake to avoid
Do not place every feature in one app component or create a generic service that owns the entire application.

Compilation and rendering

Definition: Angular compiles templates into instructions and uses application state to update rendered views.

Bootstrap creates the root application and its injectors. Components are instantiated, bindings are evaluated, and Angular schedules view updates when it receives relevant notifications. Angular does not require a virtual-DOM mental model. Know the difference between compile-time template checking and actual runtime rendering.

Real project use: Trace why a changed booking status appears in a component template.

Typescript · learning example
import { Component, signal } from "@angular/core";
@Component({ selector: "app-root", standalone: true, template: `<p>{{ status() }}</p>` })
export class App {
  status = signal("pending");
}

Code explained:

  1. The decorator defines the selector and template metadata.
  2. signal stores the current status; status() reads it in the template.
  3. A later status.set("confirmed") notifies consumers so the view can update.
Mistake to avoid
Changing an unrelated plain field from an unnotified callback may not schedule a view refresh, especially with zoneless and OnPush.

Interview practice

Angular versus AngularJS?

AngularJS is the older 1.x framework with a different architecture. Modern Angular is the TypeScript-oriented component framework; do not mix their APIs or learning materials.

Try it yourself

Explain where room fetching, room display, and navigation belong.

Show a possible solution

Room fetching belongs in an API/data-access boundary, display in components, and URL navigation in the router.

Angular CLI, Workspace & First App

Use the CLI to start from a supported project configuration rather than assembling the framework manually.

Creating and serving a project

Definition: The CLI generates, builds, serves, tests, and updates Angular workspaces.

ng new creates a workspace and app; ng serve runs a development server; ng build creates deployment output; ng generate creates framework files. Choose a supported Node version using Angular’s version compatibility page. The development server is not a production hosting strategy.

Real project use: Start a hospitality frontend with routing and a maintainable stylesheet choice.

Bash · learning example
npx @angular/cli@22 new hospitality-ui --routing --style=css
cd hospitality-ui
npm start
# Separate terminal:
npx ng build
npx ng test

Code explained:

  1. The versioned CLI command selects the intended major for this example.
  2. The generated project supplies framework/build configuration and package scripts.
  3. Build checks deployable output; tests check selected behavior.
Mistake to avoid
Check current Node/TypeScript/RxJS compatibility instead of assuming any globally installed versions work.

Workspace files

Definition: A workspace combines source, package metadata, compiler configuration, and build targets.

package.json lists packages and scripts; the lockfile fixes resolved dependencies; angular.json configures builders and assets; tsconfig files configure TypeScript and template checking; main.ts is a bootstrap entry. Generated filename conventions can differ by CLI version. Read the actual repository rather than expecting a fixed app.component.ts layout.

Real project use: Find why an asset is missing or why production uses a different configuration.

Typescript · learning example
// main.ts
import { bootstrapApplication } from "@angular/platform-browser";
import { App } from "./app/app";
bootstrapApplication(App).catch(error => console.error(error));

Code explained:

  1. bootstrapApplication creates a standalone application rooted at App.
  2. Root providers can be supplied in its application configuration argument.
  3. Bootstrap failures are reported instead of being silently ignored.
Mistake to avoid
Do not edit generated build output and expect the next build to retain your edits.

Interview practice

ng serve versus ng build?

ng serve hosts a development workflow with rebuilding. ng build generates output suitable for deployment. Production infrastructure must serve that output or its server entry correctly.

Try it yourself

Find the project scripts, Angular major version, and bootstrap file in a repository.

Show a possible solution

Read package.json, use ng version, and follow the app’s main entry to bootstrapApplication or its legacy module bootstrap.

Lesson 7 · Components & templates · Beginner

Standalone Components & Application Providers

Standalone components declare their template dependencies directly and can be bootstrapped without a root NgModule.

Standalone imports

Definition: A standalone component lists the components, directives, and pipes its own template needs in imports.

TypeScript import statements make names available to the file. The decorator imports array makes template dependencies available to Angular. These are separate purposes. Importing a child class in TypeScript alone does not let the parent template render it. Current Angular treats components as standalone by default, but explicit standalone:true keeps these examples clear.

Real project use: Reuse RoomCard in a RoomList without a feature NgModule.

Typescript · learning example
import { Component } from "@angular/core";
@Component({ selector: "app-room-card", standalone: true, template: `<p>Room 201</p>` })
export class RoomCard {}
@Component({ selector: "app-root", standalone: true, imports: [RoomCard], template: `<app-room-card />` })
export class App {}

Code explained:

  1. RoomCard declares the element selector app-room-card.
  2. The parent lists RoomCard in its template imports.
  3. The matching element instantiates the child component.
Mistake to avoid
Providers and template imports are different; adding a service to imports does not register it correctly.

Root providers

Definition: A provider tells dependency injection how to supply a requested dependency.

Application configuration can provide the router, HttpClient, and application tokens. A root service may also use providedIn:"root" for tree-shakable registration. Dependencies supplied at a component or route boundary may have a different lifetime. Choose the scope based on state ownership, not convenience.

Real project use: Register the API client and navigation for the whole booking app.

Typescript · learning example
import { ApplicationConfig } from "@angular/core";
import { provideHttpClient } from "@angular/common/http";
import { provideRouter } from "@angular/router";
export const appConfig: ApplicationConfig = {
  providers: [provideHttpClient(), provideRouter([])]
};

Code explained:

  1. provideHttpClient registers the HTTP infrastructure.
  2. provideRouter registers router services with the supplied route array.
  3. Pass appConfig into bootstrapApplication to apply these providers.
Mistake to avoid
A provider factory must actually be used by the bootstrap configuration; merely exporting it is insufficient.

Interview practice

Are NgModules required in modern Angular?

No for standalone application composition. Existing applications and libraries can still use NgModules, so you need to understand both registration models.

Try it yourself

Show a possible solution

The parent template needs the component in the Angular metadata imports array, not only a TypeScript import.

Lesson 8 · Components & templates · Beginner

Component Anatomy, Selectors & Styles

A component is a class plus metadata describing how it appears and behaves in the component tree.

Metadata and template ownership

Definition: @Component metadata supplies the selector, template or templateUrl, styles, and framework configuration.

A selector determines how Angular recognizes a component in a template. An inline template keeps small examples together; an external template is useful for larger views. Styles can be inline or external. The class holds state and handlers, but should not contain every business and transport concern.

Real project use: Create a small reusable badge for room availability.

Typescript · learning example
import { Component, input } from "@angular/core";
@Component({
  selector: "app-status-badge", standalone: true,
  template: `<span [class.available]="available()">{{ available() ? "Available" : "Occupied" }}</span>`,
  styles: [`.available { color: #166534; }`]
})
export class StatusBadge { available = input(false); }

Code explained:

  1. input defines data accepted from the parent.
  2. The template reads the input signal and derives a text label.
  3. The class binding selects a CSS class without manually manipulating the DOM.
Mistake to avoid
Use specific selectors and avoid global CSS fixes for an unclear component boundary.

Encapsulation and host element

Definition: Style encapsulation controls the scope of component styles; the host is the element representing the component.

Emulated encapsulation scopes styles through generated attributes, ShadowDom uses the browser shadow root, and None leaves styles global. Component selectors still have layout consequences because the host participates in the page. Prefer deliberate host styles over deep selectors that pierce another component’s internals.

Real project use: Make a room card host participate as a block in a grid.

Typescript · learning example
@Component({
  selector: "app-room-card", standalone: true,
  template: `<h2>Single room</h2>`,
  host: { "class": "room-card" },
  styles: [`:host { display: block; padding: 1rem; }`]
})
export class RoomCard {}

Code explained:

  1. The host receives the room-card class.
  2. The :host rule styles the component element itself.
  3. The template defines content inside that host.
Mistake to avoid
Do not default to deprecated deep-style workarounds when a public styling API or composition can solve the issue.

Read a decorator, class, field and method without guessing

Definition: A decorator supplies Angular metadata; the class holds behavior and state; fields store values; methods implement actions.

Why and when to use it: Think of the template as reading public view state and dispatching user intent. The selector determines how a parent instantiates the component; template declares its view. Business logic is not created by the decorator. Keep expensive repeated calculations out of templates unless they are deliberately derived/cached.

Real project scenario: A room card displays an available room and records a local selection.

Independent learning snippet · typescript
import { Component, signal } from "@angular/core";
@Component({
  selector: "app-demo-card", standalone: true,
  template: `<h2>{{ name }}</h2>
    <button type="button" (click)="select()">Select</button>
    @if (selected()) { <p>Selected locally</p> }`
})
export class DemoCard {
  readonly name = "Garden Suite";
  readonly selected = signal(false);
  select(): void { this.selected.set(true); }
}

Code explained step by step:

  1. Component metadata connects this class with app-demo-card and its template.
  2. name is a constant display field; selected is changing reactive state.
  3. The click calls a class method; the method updates the signal.
  4. @if conditionally displays the selected message.

Expected behavior: Import DemoCard into a parent’s component imports and use <app-demo-card /> to show it.

Mistake to avoid
Selecting locally does not reserve inventory; an actual booking needs an accepted server transaction.

Interview practice

Component versus directive?

A component owns a template/view. A directive adds behavior to a host element without owning a component template. Both can use inputs, injection, and host bindings.

Show a possible solution

Use input(false), read available() in the template, and choose Available/Occupied with a conditional expression.

Lesson 9 · Components & templates · Beginner

Interpolation, Property, Attribute & Event Binding

Bindings connect class values to the template and user interaction back to behavior.

Interpolation and property binding

Definition: Interpolation inserts evaluated text; property binding assigns a value to an element, directive, or component property.

{{ expression }} produces displayed text. [disabled] controls the actual boolean property, while disabled="false" still supplies a boolean attribute and may disable the control. Attribute binding uses [attr.name] for attributes such as aria-label or colspan when an attribute is intended. Do not build HTML strings to display untrusted content.

Real project use: Show a price, disable booking while saving, and supply an accessible label.

Markup · learning example
<!-- Class provides price, saving, and roomName. -->
<p>{{ price }}</p>
<button [disabled]="saving" [attr.aria-label]="'Book ' + roomName">Book</button>

Code explained:

  1. price is displayed as text rather than interpreted HTML.
  2. disabled receives a boolean from saving.
  3. aria-label is an attribute bound to a descriptive string.
Mistake to avoid
String attributes and live DOM properties are related but not interchangeable.

Event binding and $event

Definition: Event binding registers a template handler for an event or component output.

(click)="save()" invokes the handler when activated. $event contains the event payload. For native input events, its target is broadly typed, so a template reference to a known input can make reading its value simpler. Handle form submission at the form rather than only at its button.

Real project use: Update a room-search signal as the user types.

Markup · learning example
<!-- Class provides query = signal(""). -->
<input #searchBox (input)="query.set(searchBox.value)" aria-label="Search rooms">
<button type="button" (click)="query.set('')">Clear</button>

Code explained:

  1. #searchBox gives a template reference to the input element.
  2. The input event reads that element’s current value and updates query.
  3. Clear is explicitly a non-submit button.
Mistake to avoid
Do not call a handler while registering a JavaScript listener; template event expressions and listener registration have different syntax.

Property binding versus attribute binding in a real control

Definition: A DOM property controls the live element object; an HTML attribute supplies markup metadata and may have different semantics.

Why and when to use it: Use [disabled] for a live button property and [attr.aria-label] or [attr.aria-invalid] for accessibility attributes. Interpolation in a text node displays text.   1. disabled receives a real boolean from pending().
  2. The aria label is a string attribute describing the action.
  3. Interpolation displays the room name as text.

Template Expressions, References & @let

Expression scope and template references

Definition: A template can read component members and its own local variables or references.

Use concise expressions for display. Complex transformations belong in computed values, pure functions, pipes, or the data layer. Template references can point to elements or exported directive instances. References and local variables have scope; a reference inside a repeated or conditional view is not universally available. Angular templates support a subset of JavaScript syntax with their own semantics.

Real project use: Read an input element and avoid repeated expensive calculations.

Code explained:

  1. @let defines a template-local value for reuse in its scope.
  2. rooms() reads the signal; its length becomes count.
  3. The element reference provides the input value at click time.
Mistake to avoid
Do not make expensive impure methods run repeatedly from bindings.

Safe reads and pure presentation

Definition: Presentation expressions should be predictable and handle absent data deliberately.

Optional chaining and nullish fallbacks keep missing data from causing errors or misleading text. Formatting belongs in a pipe when appropriate.   3. ?? uses the fallback only for absence, not every falsy value.
Mistake to avoid
A fallback should distinguish loading, absence, and failure if those are different user states.

Why avoid calling API methods in interpolation?

@if and @switch

Definition: @if conditionally renders a branch; @switch selects a branch based on a value.

An @if block can capture a result with an alias and pair with @else. @switch is useful for finite named states. Removing a branch destroys its view and associated instances, unlike merely hiding it with CSS. Model loading, success, empty, and error explicitly so users can understand what happened.

Real project use: Display the correct state for a room API result.

Code explained:

  2. Each named case has its own presentation.
  3. The fallback covers an initial state instead of assuming data is already loaded.
Mistake to avoid
CSS hiding preserves instances and resources; structural removal has lifecycle consequences.

Mistake to avoid

Inputs, Required Inputs, Aliases & Transforms

Inputs let a parent supply data to a component through a declared public contract.

Signal inputs

Definition: input creates a read-only input signal; input.required requires the caller to supply a value.

Read the value with parentheses and derive presentation with computed. An optional/default input has a declared fallback. Inputs are parent-owned contracts, not local writable signals. Mutating a nested input object still changes shared data even if the input signal itself is read-only. Prefer child outputs to request changes from the owner.

Real project use: Pass a Room record into a reusable room card.

Typescript · learning example
import { Component, computed, input } from "@angular/core";
interface Room { id: number; name: string; price: number; available: boolean }
@Component({ selector: "app-room-card", standalone: true, template: `<h2>{{ label() }}</h2>` })
export class RoomCard {
  room = input.required<Room>();
  label = computed(() => `${this.room().name}: ${this.room().price}`);
}

Code explained:

  1. The required input defines the parent’s obligation.
  2. computed derives a label from the current room.
  3. The template reads label() and updates when its dependency changes.
Mistake to avoid
Do not eagerly read a required input before Angular has assigned it; derive or read it at a valid point.

Aliases, transforms, and legacy decorators

Definition: An alias changes the binding name; a transform normalizes accepted input values; @Input is the established decorator alternative.

Use an alias for a deliberate public API, not to obscure naming. Built-in booleanAttribute/numberAttribute transforms are useful for attribute-like values, but their coercion behavior is not a full business validator. Existing projects can use @Input() fields and ngOnChanges. Do not mix styles randomly within a component without a migration reason.

Real project use: Accept a boolean compact mode on a UI component.

Typescript · learning example
import { booleanAttribute, input } from "@angular/core";
// Inside a component class:

Code explained:

  1. The input defaults to false.
  2. The transform normalizes supported incoming attribute-like values.
  3. The signal is still read as compact().
Mistake to avoid
An input transform is not permission checking or validation of all domain rules.

Interview practice

Why use a required input?

It makes the component contract explicit and enables compile-time checking of missing bindings. It does not validate malicious runtime objects received elsewhere.

Outputs, model & Component Communication

Use inputs for data entering a component and outputs for events leaving it.

Output events

Definition: output declares a component event that callers can bind to in templates.

An output carries an application payload rather than a browser event unless you choose that payload. Angular component outputs do not automatically bubble through the DOM. Choose an event name describing what happened, such as booked or selected, and let the parent decide the business action. EventEmitter with @Output remains common in legacy code.

Real project use: A RoomCard requests booking while its parent owns navigation and API submission.

Typescript · learning example
import { Component, input, output } from "@angular/core";
@Component({ selector: "app-room-card", standalone: true, template: `<button (click)="bookRequested.emit(roomId())">Book</button>` })
export class RoomCard {
  roomId = input.required<number>();
  bookRequested = output<number>();
}
// Parent template: <app-room-card [roomId]="201" (bookRequested)="book($event)" />

Code explained:

  1. The parent supplies a room ID through an input.
  2. Clicking emits that ID as a typed event payload.
  3. The parent’s book handler controls the resulting operation.
Mistake to avoid
Do not assume a component output bubbles to every ancestor as a native click event would.

model and two-way component bindings

Definition: model creates a writable signal input with a corresponding change output for two-way binding.

Use it for controls whose public contract is editable state, such as a quantity selector. The generated output convention allows [(value)]-style binding. Inputs alone are read-only from the child’s perspective; model deliberately exposes a synchronized write contract. Two-way binding is convenient but can obscure ownership if overused across unrelated components.

Real project use: A nights picker updates the parent’s chosen booking duration.

Typescript · learning example
import { Component, model } from "@angular/core";
@Component({ selector: "app-nights", standalone: true, template: `<button (click)="nights.update(n => n + 1)">+</button><span>{{ nights() }}</span>` })
export class NightsPicker { nights = model(1); }
// Parent with nights = signal(1): <app-nights [(nights)]="nights" />

Code explained:

  1. model initializes an editable numeric value.
  2. update changes it and notifies the associated change output.
  3. The parent’s writable signal is passed as the two-way binding target, not its current numeric result.
Mistake to avoid
Do not use a two-way model merely to avoid designing clear input/output responsibilities.

Interview practice

Sibling component communication?

Use a common parent with inputs/outputs when state belongs there. Use a scoped shared service/store when siblings need a wider feature-owned state contract. Avoid global event buses for every interaction.

Lifecycle Hooks & Resource Ownership

Lifecycle hooks let code react to component creation, input changes, view readiness, and destruction.

Constructor, ngOnChanges, and ngOnInit

Definition: The constructor creates the instance; ngOnChanges responds to input changes; ngOnInit runs once after initial inputs are initialized.

Use the constructor or field initialization for dependency injection and initial definitions, not for assumptions that required inputs are already assigned. ngOnChanges precedes the initial ngOnInit when applicable and can distinguish first changes. Signal inputs with computed values often remove the need to manually copy changes into derived fields.

Real project use: Initialize a feature once and respond to a changed room ID without stale derived state.

Typescript · learning example
import { Component, Input, OnChanges, SimpleChanges } from "@angular/core";
@Component({ selector: "app-room-title", standalone: true, template: `<p>Room {{ roomId }}</p>` })
export class RoomTitle implements OnChanges {
  @Input() roomId = 0;
  ngOnChanges(changes: SimpleChanges): void {
    if (changes["roomId"]) console.log("Room changed", this.roomId);
  }
}

Code explained:

  1. @Input declares the legacy public input.
  2. ngOnChanges receives metadata for changed inputs.
  3. The handler sees Angular-assigned input data instead of constructor defaults.
Mistake to avoid
ngOnInit runs once per instance, not each time an input or route parameter changes.

Content/view hooks and destruction

Definition: Content hooks concern projected content; view hooks concern the component’s own initialized view; destruction marks the end of instance ownership.

ngAfterContentInit and ngAfterViewInit run once at their respective stages. Checked hooks run frequently and should not perform expensive work. Avoid changing already-checked bindings in a hook just to force a rendering cycle. DestroyRef provides cleanup tied to the current injection context, and ngOnDestroy remains a common class hook.

Real project use: Remove a third-party event listener when the owning view is removed.

Typescript · learning example
import { DestroyRef, inject } from "@angular/core";
// Component field/constructor context:
const destroyRef = inject(DestroyRef);
const onResize = () => console.log("resize");
window.addEventListener("resize", onResize);
destroyRef.onDestroy(() => window.removeEventListener("resize", onResize));

Code explained:

  1. The same handler identity is registered and later removed.
  2. DestroyRef ties cleanup to the component/service scope in which it was injected.
  3. The example is browser-only; an SSR-compatible implementation must guard its browser dependency.
Mistake to avoid
A root-owned cleanup scope lasts much longer than a component-owned scope.

Initialize inputs, react to changes and clean up by ownership

Definition: Lifecycle hooks are framework callbacks at defined points in a component’s lifetime.

Why and when to use it: Use input-derived computed values when possible rather than repeatedly copying inputs in hooks. ngOnInit suits initialization after initial inputs exist. ngOnChanges handles supported decorator-input changes. afterNextRender suits browser DOM work after rendering when needed. DestroyRef or ngOnDestroy release owned resources. Do not perform heavy work in frequently called checked hooks.

Real project scenario: A details page owns a polling subscription or third-party chart and releases it when removed.

Independent learning snippet · none
// Ownership sketch:
// create component -> resolve dependencies
// initialize inputs -> initialize input-dependent work
// render -> perform necessary browser DOM integration
// later updates -> react to changed state/inputs
// destroy -> release owned timers/listeners/chart instances

Code explained step by step:

  1. The constructor is not proof parent inputs have already arrived.
  2. DOM integration belongs at the appropriate render/browser boundary.
  3. Destruction has a concrete cleanup responsibility.

Expected behavior: The feature has an understandable start/update/stop lifecycle.

Mistake to avoid
A setTimeout workaround can hide a timing bug without providing correct lifetime cleanup.

Interview practice

constructor versus ngOnInit?

The constructor is JavaScript instance initialization and an injection context. ngOnInit is an Angular lifecycle hook after initial inputs are assigned. Choose based on data readiness, not a blanket rule.

Queries should not replace a well-defined data contract between components.

Definition: AsyncPipe subscribes to an Observable or Promise, exposes its latest result, and manages the subscription.

@Injectable({ providedIn: "root" })
export class PricingService {
  estimate(nightlyPrice: number, nights: number): number {
    if (!Number.isFinite(nightlyPrice) || nightlyPrice < 0) {
      throw new Error("Nightly price must be finite and nonnegative");
    }
    if (!Number.isInteger(nights) || nights < 1) {
      throw new Error("Nights must be a positive integer");
    }
    return nightlyPrice * nights;
  }
}

Code explained step by step:

  1. Injectable marks the class for Angular DI; providedIn root supplies a shared root registration.
  2. Validation rejects invalid estimates rather than silently accepting NaN or fractional nights.
  3. The returned number is a client estimate; currency rounding, discounts, taxes, and final totals require explicit business rules.

Expected behavior: estimate(120, 3) returns 360; estimate(120, 0) throws.

Mistake to avoid
Do not throw an error from a frequently evaluated template expression; validate user input and handle expected errors before requesting an estimate.

Signals: signal, set, update & computed

A signal stores a value and lets Angular track which reactive consumers read it.

Writable signals and immutable updates

Definition: signal creates writable reactive state; set replaces the value and update derives a replacement from the current value.

Read it with parentheses. Reactive notification is connected to accepted value changes; mutating an object in place while retaining the same reference can bypass the intended update behavior. Keep ownership private when exposing shared state and offer readonly views or explicit methods. Signals are synchronous state values rather than asynchronous streams.

Real project use: Track selected room IDs and cart totals.

Typescript · learning example

const price = signal(1200);

console.log(total());

Code explained:

  1. update changes nights from 1 to 2.
  2. computed reads the signals and tracks those dependencies.
  3. The total is 2400 and is recalculated when its dependencies invalidate it.
Mistake to avoid
Call the signal to read it; do not assign a new value to the signal variable instead of using set/update.

Computed derivation

Definition: computed creates readonly derived state from signal reads.

Use it for filtered lists, totals, and presentation values instead of copying source state through an effect. It is lazy and memoized until tracked dependencies invalidate it. Dependencies are dynamic: only values actually read during the executed branch are tracked. Do not perform API writes or other side effects inside computed.

Code explained:

  1. The derivation reads both source list and query.
  2. It creates the visible list without changing the source.
  3. Consumers share a derived value rather than maintaining a second independently writable list.
Mistake to avoid
Avoid computed values that depend on non-reactive variables you expect Angular to track magically.

Interview practice

Signals versus Observables?

Signals model synchronous current state and dependency tracking. Observables model emissions over time, completion, errors, and asynchronous composition. They can be bridged rather than treated as competing replacements.

Create it in a valid injection context. It is appropriate for deliberate external synchronization, such as persisting a preference or updating an external library. Reactive params and loader lifecycle

Definition: resource derives loading parameters and exposes value, loading, status, and error state.

A params computation follows source signals; a loader receives params and an abortSignal. Returning undefined params can keep the resource idle. Resources are designed primarily for reads: changing params can cancel outstanding loading. A mutation such as creating a booking needs deliberate command handling and should not be silently canceled by a reactive read lifecycle. API details depend on your Angular version.

});

Code explained:

  1. roomId becomes the reactive loading parameter.
  2. The loader checks HTTP success and connects cancellation to fetch.
  3. The result remains unknown until runtime validation establishes the Room contract.
Mistake to avoid
Do not use a reactive read resource as a fire-and-forget command API for writes.

Definition: Resource state must be inspected before assuming a value is present or safe to read.

Use hasValue and explicit loading/error handling. A value read can throw in an error state for supported resource APIs. httpResource integrates Angular HTTP request handling with signal resource state and can accept parsing/validation configuration; RxJS interoperability also offers async resource patterns. RxJS supplies composable streams for HTTP, forms, events, and application workflows.

Observable lifecycle

Definition: An Observable describes a producer that can emit next values, fail with error, or finish with complete.

Completion/error ends that subscription; a stream does not need to emit exactly one value. pipe composes operators without subscribing.   2. map transforms each emission rather than the whole stream into an array.
  3. subscribe receives 200 and 400, then completion.

A trailing $ is a naming convention, not syntax that makes a value observable.

Lesson 28 · RxJS · Beginner

Observable Workshop: Subscribe, Pipe & Cleanup

Understand the basic stream mechanism before learning many operators. The first example runs without HTTP.

Creation is different from execution

Definition: An Observable defines how values are delivered to a subscriber; a subscription is one execution/connection to that stream.

Why and when to use it: Many observables are lazy. A subscriber can receive next values, then one error or complete terminal notification. Unsubscription triggers registered teardown; it does not mean complete was emitted. Observables may emit synchronously or asynchronously. Whether work is shared depends on the source/operators.

Real project scenario: Explain why a service method that returns an observable has not necessarily fetched anything yet.

Independent learning snippet · typescript
import { Observable } from "rxjs";
const source = new Observable<number>(subscriber => {
  console.log("started");
  subscriber.next(1);
  subscriber.next(2);
  subscriber.complete();
  return () => console.log("cleanup");
});
console.log("created");
source.subscribe({
  next: value => console.log("value", value),
  complete: () => console.log("complete")
});

Code explained step by step:

  1. Constructing source stores the producer function without running it.
  2. subscribe starts this synchronous producer and receives 1 then 2.
  3. complete closes the subscription; the returned teardown is run.

Expected behavior: The order is created, started, value 1, value 2, complete, cleanup.

Mistake to avoid
Calling an Observable asynchronous by definition is incorrect; this producer is synchronous.

pipe transforms the stream; subscribe consumes it

Definition: pipe combines operators into a new stream, while subscribe attaches a consumer.

Why and when to use it: map transforms values; tap is for deliberate side effects/inspection without replacing values. A component can consume through AsyncPipe or toSignal rather than manually subscribing for display-only state. Do not nest a subscription inside map or use tap as a transformation.

Real project scenario: Convert server room records into display labels while keeping request handling composable.

Independent learning snippet · typescript
import { of, map, tap } from "rxjs";
const names = of(["Garden", "City"]).pipe(
  map(items => items.map(name => name.toUpperCase())),
  tap(items => console.log("diagnostic", items.length))
);
names.subscribe(items => console.log(items));

Code explained step by step:

  1. of emits one array, not one emission per array item here.
  2. The RxJS map transforms that array using the array’s own map method.
  3. tap observes the transformed array and preserves it.
  4. subscribe receives the resulting ["GARDEN", "CITY"].

Expected behavior: The diagnostic count is 2 and the final emitted value is the uppercase array.

Mistake to avoid
Array.map and RxJS map have different receivers: one transforms array entries; the other transforms stream emissions.

Teardown for timers and long-lived streams

Definition: Teardown releases work associated with a subscription when it is closed.

Why and when to use it: HTTP response streams usually finish, while events/timers/state streams can keep running. Use Angular ownership bridges or takeUntilDestroyed where appropriate. Remember that a finite request can still outlive a removed component if it is not owned properly. Pass DestroyRef when creating the pipeline outside the injection context.

Real project scenario: Stop a dashboard polling stream when its page is removed.

Independent learning snippet · typescript
// Component sketch; imports interval/takeUntilDestroyed/inject/DestroyRef.
private readonly destroyRef = inject(DestroyRef);
startPolling(): void {
  interval(5000).pipe(
    takeUntilDestroyed(this.destroyRef)
  ).subscribe(() => this.refresh());
}

Sync, Async & Cross-field Validation

Validators check input constraints and return structured errors rather than silently changing the data.

Synchronous and cross-field validators

Definition: A synchronous validator returns validation errors or null. Cross-field rules belong at the relevant group boundary.

Field validators handle a single value. A group validator can compare arrival/departure dates or password/confirmation. Keep validators pure and account for incomplete input before asserting a relationship. Do not repeatedly mutate child errors inside a group validator when a group-level error can express the problem cleanly.

Real project use: Require checkout to follow check-in.

Typescript · learning example
import { AbstractControl, ValidationErrors, ValidatorFn } from "@angular/forms";
export const datesInOrder: ValidatorFn = (group: AbstractControl): ValidationErrors | null => {
  const start = group.get("checkIn")?.value;
  const end = group.get("checkOut")?.value;
  if (!start || !end) return null;
  return end > start ? null : { datesInOrder: true };
};

Code explained:

  1. The validator reads sibling fields from the group.
  2. Incomplete values are left to required validators.
  3. The comparison works for a deliberate normalized date-only representation; do not apply it to arbitrary localized text.
Mistake to avoid
Date parsing/timezones and domain semantics must be specified, not guessed.

Asynchronous validation and pending state

Definition: An async validator returns a Promise or Observable of errors/null while the control is pending.

Use it for remote availability/uniqueness checks, not as the final guarantee that a booking will succeed. Avoid unbounded/live observables in validator results. updateOn:"blur" or a deliberate delay policy can reduce request traffic. Handle remote failure differently from “already taken” if those states have different meaning. Server constraints remain authoritative during submission.

Real project use: Check a username or reference code before submission without requesting on every keystroke.

None · learning example

// updateOn: "blur"
// AsyncValidatorFn returns a finite Observable<ValidationErrors | null>.
// UI must account for control.pending and a server-check failure.

Code explained:

  1. Blur timing reduces validation frequency.
  2. The finite result allows pending validation to settle.
  3. The backend must recheck the condition atomically when saving.
Mistake to avoid
An earlier “available” result can become stale before submit.

Cross-field validation for a meaningful project rule

Definition: A group validator checks relationships between controls and stores the error on their shared group.

Why and when to use it: Use a group-level check when one field depends on another, such as maximum guests relative to capacity. Fields must first have valid individual values. Decide how group errors are displayed and associated with controls. The backend repeats the rule using authoritative capacity.

Real project scenario: Prevent a booking draft from declaring more guests than its entered demo capacity.

Independent learning snippet · typescript
import { ValidatorFn } from "@angular/forms";
export const capacityValidator: ValidatorFn = group => {
  const guests = group.get("guests")?.value;
  const capacity = group.get("capacity")?.value;
  if (!Number.isInteger(guests) || !Number.isInteger(capacity)) return null;
  return guests > capacity ? { capacityExceeded: true } : null;
};
// Register on FormGroup options: { validators: [capacityValidator] }
// Template checks group.hasError("capacityExceeded") after interaction.

Code explained step by step:

  1. The validator reads sibling controls through the group.
  2. It avoids duplicating their individual integer validation.
  3. A failed relationship returns a named group error.
  4. The template checks the group, not only a single control’s errors.

Expected behavior: Guests 4 and capacity 2 yield capacityExceeded on the group.

Mistake to avoid
A user-editable capacity is only a demo input; production capacity must come from trusted room data and be checked by the server.

Interview practice

Can an async uniqueness validator guarantee no duplicate booking?

No. Another operation can change the database after validation. The server needs authoritative validation, concurrency handling, and appropriate constraints.

Definition: A ControlValueAccessor connects a custom UI to Angular’s established forms APIs.

Signal Forms custom-control interfaces differ and should be implemented according to that system.

Real project use: Build a reusable numeric nights picker that works with reactive forms.

Typescript · learning example
import { ControlValueAccessor } from "@angular/forms";

  setDisabledState(disabled: boolean): void { this.disabled = disabled; }
}

Code explained:

  1. The model writes into value through writeValue.
  2. Callbacks are stored rather than invoked at registration time.
  3. Real user actions update the view and call onChange; blur/completed interaction calls onTouched.

This contract sketch still needs provider metadata, rendering/notification, keyboard behavior, and user-event methods.

Functional interceptor chain

Definition: An interceptor receives a request and a next function and returns the resulting event stream.

Clone requests for immutable changes. The configured order determines the chain; response handling flows back through it. Register functional interceptors with withInterceptors. Only attach credentials to approved API destinations, not every outgoing URL. Avoid making business-specific mutations invisible in a global interceptor.

  if (!request.url.startsWith("/api/")) return next(request);
  const updated = request.clone({ setHeaders: { "X-Client": "hospitality-ui" } });
  return next(updated);
};
// providers: [provideHttpClient(withInterceptors([correlation]))]

Code explained:

  1. Non-API requests pass through untouched.
  2. clone creates an updated request rather than mutating it.
  3. next continues the chain and returns its observable response/event behavior.
Mistake to avoid
A URL-prefix check is an illustrative policy; production absolute URLs need a carefully validated origin/path allowlist.

Definition: HttpContext carries typed request metadata for policies without placing it in HTTP headers.

A context token can disable a spinner or select a cache policy. Global handlers must not turn every error into a login redirect; 401, 403, validation failures, cancellation, and network failures have different meanings. export interface Room {
  id: number; name: string; price: number; available: boolean;
}
export function parseRooms(value: unknown): Room[] {
  if (!Array.isArray(value)) throw new Error("Expected room array");
  return value.map((item: unknown) => {
    if (typeof item !== "object" || item === null) {
      throw new Error("Invalid room record");
    }
    const room = item as Record<string, unknown>;
    if (typeof room["id"] !== "number" ||
        !Number.isInteger(room["id"]) || room["id"] < 1 ||
        typeof room["name"] !== "string" || !room["name"].trim() ||
        typeof room["price"] !== "number" ||
        !Number.isFinite(room["price"]) || room["price"] < 0 ||
        typeof room["available"] !== "boolean") {
      throw new Error("Invalid room fields");
    }
    return { id: room["id"], name: room["name"],
      price: room["price"], available: room["available"] };
  });
}

Code explained step by step:

  1. The first check establishes an array before map runs.
  2. The object/null check makes property inspection safe.
  3. Each field is checked before building the returned trusted object.
  4. The cast to a generic record permits inspection; it does not claim the values are already a Room.

Expected behavior: parseRooms returns Room[] for the fixture and throws for invalid record shapes.

Mistake to avoid
Replacing the checks with value as Room[] removes validation without changing the server response.

import { toSignal } from "@angular/core/rxjs-interop";
import { RouterLink } from "@angular/router";
import { Subject, catchError, map, of, startWith, switchMap } from "rxjs";
import { RoomApi } from "./room-api";
import { Room } from "./room.model";

type RoomState =
  | { kind: "loading" }
  | { kind: "error"; message: string }
  | { kind: "ready"; rooms: Room[] };

@Component({
  selector: "app-room-list", standalone: true, imports: [RouterLink],
  template: `
    <h1>Rooms</h1>
    <label for="query">Search room name</label>
    <input id="query" [value]="query()" (input)="onSearch($event)">
    @if (state().kind === "loading") { <p role="status">Loading rooms…</p> }
    @if (state(); as current) {
      @if (current.kind === "error") {
        <p role="alert">{{ current.message }}</p>
        <button type="button" (click)="refresh()">Try again</button>
      }
      @if (current.kind === "ready") {
        <p aria-live="polite">{{ visible().length }} matching rooms</p>
        <ul>
          @for (room of visible(); track room.id) {
            <li><a [routerLink]="['/rooms', room.id]">{{ room.name }}</a>
              — {{ room.price }} USD/night
              @if (!room.available) { <span> — unavailable</span> }
            </li>
          } @empty { <li>No matching rooms. Try another search.</li> }
        </ul>
      }
    }
  `
})
export class RoomList {
  private readonly api = inject(RoomApi);
  private readonly reload = new Subject<void>();
  readonly query = signal("");
  readonly state = toSignal(this.reload.pipe(
    startWith(undefined),
    switchMap(() => this.api.list().pipe(
      map((rooms): RoomState => ({ kind: "ready", rooms })),
      catchError(() => of<RoomState>({
        kind: "error", message: "Could not load rooms. Try again."
      })),
      startWith<RoomState>({ kind: "loading" })
    ))
  ), { initialValue: { kind: "loading" } as RoomState });
  readonly visible = computed(() => {
    const current = this.state();
    if (current.kind !== "ready") return [];
    const query = this.query().trim().toLowerCase();
    return current.rooms.filter(room => room.name.toLowerCase().includes(query));
  });
  refresh(): void { this.reload.next(); }
  onSearch(event: Event): void {
    if (event.target instanceof HTMLInputElement) {
      this.query.set(event.target.value);
    }
  }
}

import { Injectable, inject } from "@angular/core";
import { Observable, map, switchMap, throwError, timer } from "rxjs";
import { RoomApi } from "../rooms/room-api";

export interface BookingRequest { roomId: number; guestName: string; nights: number; }
export interface DemoReceipt { demoId: number; roomId: number; estimatedTotal: number; }
@Injectable({ providedIn: "root" })
export class DemoBookingApi {
  private readonly rooms = inject(RoomApi);
  private nextId = 1;
  save(request: BookingRequest): Observable<DemoReceipt> {
    if (!request.guestName.trim() || !Number.isInteger(request.nights) || request.nights < 1) {
      return throwError(() => new Error("Invalid demo booking"));
    }
    return this.rooms.list().pipe(switchMap(rooms => {
      const room = rooms.find(item => item.id === request.roomId);
      if (!room?.available) {
        return throwError(() => new Error("Room unavailable in fixture"));
      }
      return timer(600).pipe(map(() => ({
        demoId: this.nextId++, roomId: room.id,
        estimatedTotal: room.price * request.nights
      })));
    }));
  }
}

Angular versus TypeScript?

TypeScript is a language/toolchain with static types. Angular is an application framework using it, providing components, templates, DI, routing, forms, rendering, and tooling.

Standalone versus NgModule?

It describes item identity across list updates and helps preserve matching views. Index identity can associate a reused view with the wrong item when ordering changes.

A token resolves through an injector hierarchy. Where a provider is registered determines visibility and instance lifetime; root and component providers may create different instances.

No. Inputs, reactive notifications, events, and explicit marks can trigger checks according to the supported rendering model. Understand the project version and mutation patterns.

Interview practice

Exercise: implement latest-only search.

Use an input stream with the required debounce/distinct policy, switchMap to the read request, and catchError inside the inner stream when you want later queries to keep working. Represent loading, empty, failure and success explicitly.

Exercise: validate a date range.

Use a group-level validator comparing valid dates with explicit business/timezone rules. Return a stable error key, associate the message with controls, and independently enforce the rule on the server.

Exercise: test a failed save.

Make the service fail predictably, invoke submission, verify pending state resets, the draft remains when appropriate, an actionable error appears, and no success navigation occurs.

Exercise: split a large component.

Identify responsibilities before extracting. Keep the page orchestration, move coherent display/interaction into child components, centralize API mapping, and define explicit input/output ownership.
